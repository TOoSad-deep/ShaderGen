# 前端交互优化设计

日期：2026-07-08

## 范围

本次只优化现有“上传图片 -> 生成 GLSL -> WebGL 预览”流程，不扩展 F01 的 Idea、需求、参考设计、测试规划输入，也不改后端 API 契约。

## 目标

- 用户一打开页面就知道可以上传图片生成 Shader。
- 上传、生成中、成功、失败四种状态清楚可见。
- 用户能看到当前图片文件名、大小和预览。
- 生成完成后能方便查看和复制 GLSL。
- 布局在桌面和移动端稳定，不因状态切换明显跳动。

## 页面结构

保留单页 `App.tsx`，不新增路由和依赖。页面分三块：

1. 顶部标题和状态摘要：显示产品名、当前状态、上传入口。
2. 主工作区：左侧图片上传/原图预览，右侧 WebGL 预览。
3. GLSL 结果区：显示生成状态、错误消息、复制按钮和代码。

上传入口从小按钮改为更明显的上传区域，支持点击选择文件和拖拽文件。上传区复用原生 `<input type="file">`。

## 状态与交互

- 未上传：上传区显示“拖拽图片到这里或点击上传”，WebGL 和 GLSL 区显示空状态。
- 已上传未运行：展示原图，启用“开始运行”按钮，不自动调用后端生成。
- 已上传且生成中：展示原图，“开始运行”按钮进入忙碌态，避免重复提交。
- 成功：展示 WebGL 预览、GLSL 代码和复制按钮。
- 失败：保留原图，展示用户可读错误；用户可重新上传。
- 复制 GLSL：使用 `navigator.clipboard.writeText`，成功后短暂显示“已复制”。

## 错误处理

前端只展示可理解的错误文案。后端非 2xx 响应仍由 `frontend/src/api/shader.ts` 转成 `Error`；页面负责把错误放在结果区和状态摘要里。WebGL 编译或浏览器不支持 WebGL 的错误保留在预览组件内显示。

## 文件影响

- `frontend/src/App.tsx`：增加拖拽状态、文件元信息、手动开始运行、复制状态和更清晰的页面状态。
- `frontend/src/api/shader.ts`：解析 FastAPI JSON 错误体中的 `detail`，避免把原始 JSON 展示给用户。
- `frontend/src/styles/app.css`：调整布局、上传区、状态、按钮、代码区样式。
- `PROGRESS.md`：记录本次设计和后续验证结果。
