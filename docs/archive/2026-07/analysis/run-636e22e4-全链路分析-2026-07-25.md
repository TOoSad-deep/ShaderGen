## 四个核心问题（按严重性排序）

1. **Refine 钻牛角尖，结构性 patch 在严格选择下天然吃亏。** 任何结构性 patch（整层重写/删除）的参数是"生"的，要和经过多轮参数优化的现任 best 直接比 loss，几乎必输。模型只有做无关痛痒的微调才可能被接受，被困在局部最优；从没有人尝试 `remove_layer(legacy_shadow_1)` 或重写 `legacy_body`，尽管这两项才是 loss 大头。
2. **temperature=0 导致重复死循环。** patch 被拒后 current_best 不变、上下文几乎不变，模型确定性地重复同一提案；无连续重复早停机制，约 150s LLM 调用纯浪费。
3. **初始 LLM 场景被 strict 选择整体丢弃**，初始调用零收益。
4. **预算配比失衡**：渲染预算大量闲置，LLM 预算被重复调用烧完。

## 待优化点建议

- **patch → 先局部参数优化再严格选择**：结构性候选给一个小优化预算（如 5-10 次 draw）再与 incumbent 比较，否则 remove/replace 层永远赢不了。这是解锁几何修复的关键。
- **打破重复循环**：refine 被拒 N 次后升温（temperature>0）或强制更换 operation/layer；连续 2-3 次 duplicate 直接早停，剩余预算让给参数优化器。相关代码：`src/agent/app/nodes/png_to_shader_min/model_author.py`（`LLMCallOptions.temperature=0`）、`src/agent/app/nodes/png_to_shader_min/shader_graph_runtime.py`（refine 循环与 duplicate 拦截）。
- **重新评估 author_initial 定位**：要么让初始场景带一轮自渲染自评再参选，要么从 perception_fallback 起步、把 LLM 预算全给 refine。
- **residual 摘要按 loss 贡献排序**：`spatial_residual_summary` 应明确标注各分量占比（如 "geometry_mask_loss 占 31%"），让 prompt 里"修复最主导问题"有据可依。相关 prompt：`src/agent/app/prompts/shader_graph_author_refine_v1.yaml`。
- **目标校准或能力提升**：geometry 一项贡献 0.016，现有 DSL 表达力下 target_loss 0.02 不可达；要么放宽目标，要么先解决结构性 patch 选择问题。
- 次要：canvas 245×256 只有参考图一半分辨率，锐利高光 streak 天然表达不了；渲染预算富余，可考虑一次 refine 出 best-of-N 候选并行渲染。

## 建议的下一步

先做"连续 duplicate 早停 + refine 失败后升温"，见效快、风险小；随后实现"结构性 patch 先局部优化再选择"。
